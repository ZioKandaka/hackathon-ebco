# Data Model & Domain Entities: Route-Based Accessibility AI Skill

## 1. Core Domain Entities

### AccessibilityRequest
Represents a user's travel-time accessibility analysis session.

| Field | Type | Required | Description / Constraints |
|---|---|---|---|
| `id` | `string` (UUID) | Yes | Unique request identifier |
| `userId` | `string` (UUID) | Yes | Owner user ID |
| `locationId` | `string` | Yes | Target registered location ID |
| `locationName` | `string` | Yes | Location branch name |
| `travelMode` | `enum` | Yes | `'drive'`, `'walk'`, or `'transit'` (default `'drive'`) |
| `timeMinutes` | `number` | Yes | Travel time threshold in minutes (1 to 30; default 10) |
| `createdAt` | `string` (ISO-8601) | Yes | Request creation timestamp |

---

### IsochronePolygon
Represents the spatial polygon boundary generated by road network travel time.

| Field | Type | Required | Description / Constraints |
|---|---|---|---|
| `polygonId` | `string` | Yes | Unique boundary identifier |
| `center` | `{ lat: number, lng: number }` | Yes | Origin location coordinates |
| `travelMode` | `enum` | Yes | `'drive'`, `'walk'`, or `'transit'` |
| `timeMinutes` | `number` | Yes | Analyzed time threshold |
| `coordinates` | `Array<{ lat: number, lng: number }>` | Yes | Array of 12–32 lat/lng boundary vertices forming a closed polygon |

---

### RouteCatchmentResultPayload
DTO delivered over the SSE stream when accessibility analysis finishes.

| Field | Type | Required | Description / Constraints |
|---|---|---|---|
| `analysisId` | `string` | Yes | Unique analysis session ID |
| `locationId` | `string` | Yes | Referenced location ID |
| `locationName` | `string` | Yes | Analyzed location branch name |
| `travelMode` | `string` | Yes | `'drive'`, `'walk'`, or `'transit'` |
| `timeMinutes` | `number` | Yes | Duration threshold in minutes |
| `compositeScore` | `number` | Yes | Final integer catchment score (0–100) |
| `subScores` | `CatchmentSubScores` | Yes | Reused 6 sub-scores |
| `poiCount` | `number` | Yes | Total POIs inside isochrone polygon |
| `polygonCoordinates` | `Array<{ lat: number, lng: number }>` | Yes | Polygon vertices for map overlay |
| `radiusScoreDelta` | `number` | Optional | Score variance vs previous radius analysis (if any) |
| `summary` | `string` | Yes | Human-readable accessibility explanation |

## 2. Spatial Boundary Layer Lifecycle (Frontend)

```text
[No Active Overlay] (0 layers)
        │
        ▼ User submits accessibility prompt in AI Chat Panel
[SSE Stream Active] ──► Status updates: "Determining action..." ──► "Calculating travel-time boundary..." ──► "Analyzing reachable area..."
        │
        ▼ Final SSE event received with RouteCatchmentResultPayload
[Single Overlay Policy] ──► Call activeCatchmentCircle.setMap(null) AND activeIsochronePolygon.setMap(null)
        │
        ▼ Instantiate new google.maps.Polygon({ paths: polygonCoordinates, map: this.map })
[1 Active Polygon Overlay] ──► Rendered on shared Google Map around location pin
```

## 3. Validation & Business Rules

1. **Travel Time Cap (FR-004)**: `timeMinutes` MUST NOT exceed 30 minutes. If user requests > 30 mins, cap to 30 mins and state cap in chat response.
2. **Travel Mode Fallback (FR-003)**: Default `travelMode = 'drive'` if mode is unspecified.
3. **Partition Filter Enforcement (SC-004)**: BigQuery spatial queries MUST include `regency_code` or `province_code` SQL filters.
4. **Single Spatial Boundary Policy (FR-009)**: `GoogleMapService` MUST maintain strictly 0 or 1 active spatial boundary (circle or polygon) on the map canvas.
